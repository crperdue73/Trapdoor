# G1 — `firewall.sh --apply` on a host with root

**Date:** 2026-11-06
**Host:** `test-trapdoor` / 192.168.111.45 (LXC container, `container=lxc`)
**Verdict:** apply runs, is idempotent, and **now denies traffic**. It did not
deny anything before today, through four separate defects.

---

## What was proven, and how

| Claim | Evidence |
|---|---|
| `--apply` executes on a host with root | `out/g1/apply-run1.log`, exit 0 |
| Idempotent | two applies, `diff` of `iptables -S DOCKER-USER` byte-identical |
| Rules match the decoy's real traffic | rule counters: 7 pkts on the /16 ACCEPT |
| The rules actually deny | `DROP -s 192.168.111.43` → request returns `000`, counter 7; from `.45` → `200` |

The last row is the one that matters. Everything above it was also true this
morning, on a chain that restricted nothing.

---

## The four defects

Each one made the previous fix look correct. Each was found by a counter that
refused to move, not by reading the script.

### 1. The report heredoc executed its own comments

Fixed in `bc726d2`. Comment text inside an unquoted heredoc is shell syntax:
backticks, backslash continuations, and dollar-brace expressions were all
evaluated before printing. The dry-run report emitted a rule line with its
source match silently deleted, and wrote a syntax error to stderr that nothing
was reading. **The artifact a human reads before `--apply` showed a different
rule than the script built.**

### 2. Check 7 could not see the rules it checked

Fixed in `450e726`. `verify.sh` grepped the whole ruleset for `TRAPDOOR` — a
string no rule contained. A fully-applied host reported "no TRAPDOOR rules
applied." The grep now targets the `TRAPDOOR-scope` comment marker that the
rules actually carry.

### 3. The `DOCKER-USER` chain is not consulted until after DNAT

This is the defect that mattered. `DOCKER-USER` is reached from `FORWARD`,
which runs **after** `nat PREROUTING`. By then the destination has been
rewritten to the container. Measured on `.45`, two rules at position 1:

```
DROP -d 192.168.111.45 --dport 8080   -> 0 pkts, request answers 200
DROP -d 172.22.0.2     --dport 80     -> 6 pkts, request returns 000
```

Every rule the script had ever built matched the published host port. It was
present, tidy, duplicated-checked, ended in a DROP, and matched nothing.

The rules are now derived from the `nat` DNAT rules themselves — not from
`docker port`, which prints the mapping backwards (`80/tcp -> host:8080`,
container on the left) and produced the host address a second time.

### 4. `-A` appends below Docker's own `RETURN`

Docker creates `DOCKER-USER` with a bare `RETURN` as rule 1. Appending puts
every TRAPDOOR rule underneath it, where it is unreachable. Measured: fifteen
rules applied, all present, no duplicates, chain ended in DROP, decoy
answering — and the top `RETURN` absorbed every packet while all fifteen
counters stayed at zero.

Rules are now inserted at position 1 in reverse, so `SPECS` lands in reading
order with the DROPs last.

## What I got wrong along the way

I concluded "traffic never reaches the host" twice, and both times the
evidence was bad:

- I measured `INPUT` counters and saw no change, and read that as "no traffic."
  `INPUT` was the wrong chain; the counters that mattered were `DOCKER-USER`'s.
- I stopped the decoy container as a test. The port died (`000`), which proved
  traffic *did* reach the container — and disproved my own conclusion. That
  test should have come first.
- An early "negative test" inserted a `DROP` and observed a 200, and I nearly
  recorded it as a broken firewall. A DROP that matches nothing returns 200 by
  design. A negative test is only a negative test if the rule is reachable.

The pattern in all four defects is one sentence: **the thing that reports is
not the thing that runs.** A rule that is present is not a rule that matches;
a check that cannot fail is not a check. Every defect today would have passed
review by inspection and did pass `verify.sh`.

---

## What remains unproven

- **`--apply` has only ever run on `.45`.** One host, one Docker version
  (26.1.5), one LXC. The DNAT-derivation is correct here; it is untested on a
  host where Docker uses a non-default bridge layout.
- **`LAB_CIDR` is the whole farm `/16`.** Every LXC and agent host can reach
  the decoy. That is a scope choice for a teaching lab, not a boundary. The
  deny test proves the mechanism works; it does not prove the scope is narrow.
- **No automated negative test.** The deny test above was run by hand. Until
  it lives in `verify.sh`, containment can regress to "fifteen present rules"
  and the suite will still print "all checks passed."
- The `TRAPDOOR-scope` marker requires the `comment` kernel module, which is
  present here but not guaranteed on a stripped image.
